# Как публиковать статьи

Сайт использует [Astro](https://astro.build/). Каждая статья — Markdown-файл в `src/content/blog/`. Имя файла становится адресом: `my-post.md` → `/blog/my-post/`.

## Через Codex

Можно просто попросить: «Добавь статью с этим текстом в блог как черновик» или «Опубликуй статью my-post». Codex создаст файл, проверит сборку и обновит этот сайт.

## Самостоятельно

Нужен Node.js 22.12+ (рекомендуется 24 LTS). Из папки сайта:

```sh
npm ci
npm run new-post -- my-post "Название статьи"
npm run dev
```

Открой локальный адрес, который напечатает сервер, и перейди в Blog. Черновики видны только при `npm run dev` и помечены «Local preview only».

Можно создать файл вручную, скопировав `templates/post.md`. Уже есть стартовый черновик `src/content/blog/first-post.md`; его можно изменить, переименовать или удалить.

В начале файла:

```yaml
---
title: "Название статьи"
description: "Краткое описание для поисковых систем и RSS."
pubDate: 2026-10-06
draft: true
lang: ru
---
```

После второго `---` идёт текст статьи. Заголовок первого уровня сайт добавит сам; разделы начинай с `##`. `lang` — `en` или `ru`. Необязательное поле `updatedDate` показывает дату обновления.

Изображения положи в `public/images/` и вставляй так: `![Описание изображения](/images/photo.jpg)`. Всё в `public/` копируется на сайт, даже если используется только в черновике; храни там только готовые к публикации файлы.

## Публикация

1. Закончи текст, описание и поставь нужную дату.
2. Измени `draft: true` на `draft: false`.
3. Проверь результат: `npm run build`, затем `npm run preview`.
4. Попроси Codex опубликовать изменения на текущем сайте.

После публикации статья появится на главной, в `/blog/` и `/rss.xml`. Сборка полностью исключает страницы, текст и описания черновиков. Если `draft` пропущен, статья тоже считается черновиком. Статьи с будущей датой не публикуются: после наступления даты нужна новая сборка и публикация.

Файлы можно редактировать в GitHub-репозитории `vlktna/me`, в ветке `master`. GitHub Actions проверяет сборку при push и в pull request. Автоматический деплой будет подключён после выбора хостинга; текущий сайт в Sites пока обновляется через Codex.

Существующие статьи на Zalando Engineering и Vas3k Club перечислены в «Published elsewhere». Для публикации их полных версий здесь нужны тексты и, для материалов работодателя, право на перепубликацию.
